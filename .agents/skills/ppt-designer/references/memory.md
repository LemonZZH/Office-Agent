# 记忆协议

记忆是 Agent 越用越懂用户的方式。三个文件，各司一职；**合并式更新，永不整文件覆盖**。

## 文件与格式

### memory/profile.md — 偏好画像（每次任务开始必读）

```markdown
# 用户偏好画像
- 视觉: 深色系（2026-10-25，用户明确"以后都喜欢深色"）
- 品牌: 公司名 XX、品牌色 #1F3A5F、logo 在 decks/_shared/logo.png
- 结构: 汇报偏好"结论先行"
- 禁忌: 不用红绿撞色（2026-11-02）
```

### memory/feedback.md — 反馈沉淀（设计经验库）

```markdown
## 2026-10-25 · quarterly-report
- 用户反馈: "图表太密了，一页最多两个图"
- 提炼规则: 单页图表数 ≤ 2，多于则拆页
```

### memory/decks.md — 作品索引（每次交付必更）

```markdown
| deck | 日期 | 场景/风格 | 路径 | 一句话 |
|---|---|---|---|---|
| quarterly-report | 2026-10-25 | 汇报/石墨灰橙 | decks/quarterly-report/ | Q3 经营汇报 10 页 |
```

## 何时写

| 触发 | 动作 |
|---|---|
| 用户表达稳定偏好（"以后…/我喜欢…/别再…"） | profile.md 追加/更新对应条目，标注日期 |
| 用户表扬或批评某个具体设计 | feedback.md 记录 + 提炼成可执行规则（可量化就量化） |
| 一份 deck 交付 | decks.md 加一行 |
| 新会话接手旧 deck | 只读不写，除非产生新反馈 |

## 合并与冲突

- 更新条目 = 读原文 → 定位条目 → 合并改写，保留其他条目。
- 同类偏好冲突时**最新反馈优先**，旧条目保留日期标记为被取代（可追溯）。
- 模糊表述（"再高级一点"）先在当次执行中具体化，交付时把已具体化的选择写入记忆，而不是把模糊词抄进记忆。

## 边界

- memory/ 含个人数据且已被 .gitignore 排除：不提交、不贴进 issue/文档、不发送到外部服务。
- 记忆里不存 API key 等机密。
- 每条偏好带日期与来源（用户明确说 / 从行为推断），推断的条目标注 `(推断)`。
