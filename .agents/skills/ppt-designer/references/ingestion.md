# 多模态摄入规范

目标：把任意形式的输入提炼成 `brief.md`（输入来源与摘要、场景受众判断、风格决策、假设清单）+ outline 的原料。**忠实于输入，不凭空编造数据**；输入没有的数据宁可不做，也不发明。

## 一段话 / 口头需求

1. 提取：主题、可能的受众、场景（内部/对外）、已有的任何结构线索。
2. 推断并记录假设：受众与场景按措辞推断（"跟老板汇报"→汇报档；"给投资人"→路演档）；页数按场景默认。
3. 需要事实数据（市场规模、财务）而输入没有 → 两条路：留占位标注 `待补充`，或 WebSearch 查证并注明来源。默认后者，查不到才占位。
4. 结构性缺口大（如路演缺团队/融资信息）→ 主会话一次性问清，最多一轮；问不到就按假设推进并明示。

## 文档（docx / md / txt / xlsx / pdf）

| 类型 | 工具 |
|---|---|
| .md / .txt | 直接 Read |
| .docx | `markitdown <file>`（或 ZCode documents 技能读取） |
| .xlsx | `markitdown <file>` 提取表格；数据页素材直接可用 |
| .pdf | Read 工具（分页读取） |
| .pptx | `markitdown <file>` 提取文字结构 |

流程：全文读入 → 提炼大纲（保留原文数据与其来源）→ 冗余裁剪：文档篇幅 ≠ 页数，按"每页一个关键信息"重新切分 → 输入中的数据必须原样保留数值，改写只动表述。

## 图片

先判断图片的角色（可多兼）：

- **内容源**（白板照片、手写笔记、截图、报纸版面）：Read 视觉读取，提取其中的结构、文字、数据 → 作为 outline 原料。提取不出的字注明，不猜数。
- **风格参考**（用户说"照这个风格/像这样的"）：Read 视觉判读气质/版式/motif + `scripts/theme_from_image.py` 提取配色候选（--out 直接生成 theme-from-ref.js，agent 微调 FONT 与 motif 后定稿）→ 写入 brief.md 的风格决策。
- **素材**（用户提供的 logo、产品图、人像）：存入 `assets/` 直接使用；logo 注意留白与对比度。

## 已有 .pptx

- 默认：`markitdown` 提取内容 → 走本项目管线用我们的设计系统重建（风格不设限）。
- 用户要求保留原模板（"在这个模板上改"）→ 加载官方 pptx 技能的模板继承流程操作，产物仍落回 deck 工作区，brief.md 注明"模板继承"。

## 组合输入

多输入合并时：内容冲突以**时间新的、用户口头明确说的**为准；每份输入的贡献记入 brief.md（"大纲来自会议纪要，数据来自 Q3.xlsx"）。

## brief.md 格式

```markdown
# Brief — <deck 名>
- 日期: 2026-10-25  输入: 一段话 + Q3数据.xlsx
- 场景/受众: 公司季度经营汇报，管理层
- 风格决策: 汇报档-石墨灰橙（内部数据复盘，浅色高效）
- 假设: 页数取 10；增长数据仅到 Q3
- 记忆应用: 应用了 profile.md 的深色偏好？否（场景为浅色汇报，已向用户说明）
```
